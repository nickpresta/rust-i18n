# Packed translation benchmark

This benchmark compares the consumer code generated by upstream `main` at
`c47194deeee01c7ce75b883193ed96fc048df235` with the code in
[PR #148](https://github.com/longbridge/rust-i18n/pull/148) at
`dac0cac8f9dd10a166bfef4c377f541ec6faefc7`. The macOS run used that
exact PR commit. The Linux run used benchmark-branch commit `cfd9ec7`, whose
crate source is byte-identical to the PR commit; its extra files are the
benchmark workflow and harness. The branch's benchmark files do not form part
of the PR's code diff.

The same deterministic, generated YAML corpus is used for both versions at
each size. It has nested keys and about 100 bytes of YAML per translation.
This is a synthetic compile workload, not an application benchmark.

| Tier | Locales | Keys per locale | Translations | YAML bytes |
| --- | ---: | ---: | ---: | ---: |
| Small | 8 | 1,000 | 8,000 | 799,613 |
| Medium | 16 | 1,000 | 16,000 | 1,597,783 |
| Large | 32 | 1,000 | 32,000 | 3,197,799 |
| Xlarge | 49 | 17,630 | 863,870 | 87,607,370 |

## Build results

Times are median seconds reported by `/usr/bin/time` for the consumer's
`cargo build --release --offline --locked`. Resident memory is the median
maximum resident set size of a completed build, in decimal GB. There were
three builds per version at 8k and 16k, two at 32k, and one attempted at
863,870. Within a host, the upstream and PR builds used the same corpus,
toolchain, settings, and warmed dependencies.

| Host | Translations | Upstream time | PR time | Upstream peak RSS | PR peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| Linux x86_64 | 8,000 | 15.26 s | 0.57 s | 1.45 GB | 0.195 GB |
| Linux x86_64 | 16,000 | 39.95 s | 0.77 s | 2.48 GB | 0.202 GB |
| Linux x86_64 | 32,000 | 114.82 s | 1.18 s | 7.93 GB | 0.217 GB |
| Linux x86_64 | 863,870 | stopped by RSS guard | 20.77 s | unknown | 1.23 GB |
| macOS arm64 | 8,000 | 9.30 s | 0.49 s | 1.33 GB | 0.151 GB |
| macOS arm64 | 16,000 | 22.41 s | 0.82 s | 2.57 GB | 0.157 GB |
| macOS arm64 | 32,000 | 67.35 s | 1.03 s | 6.44 GB | 0.169 GB |
| macOS arm64 | 863,870 | stopped by swap guard | 14.23 s | unknown | 0.862 GB |

The Linux xlarge upstream run was stopped after sampled process-group RSS
reached 12.95 GB. The macOS upstream run was stopped when available swap
crossed the configured guard. Neither upstream build completed at xlarge, so
there is no measured xlarge speedup, finished-build peak RSS, binary size, or
runtime comparison. The archived stopped-run `seconds` field includes process
cleanup; it is not a build time or a precise time to the guard trigger.

## Runtime probes

Each completed build produced five fresh-process trials. `First` measures
time to the first translation, including lazy table initialization. `Lookup`
averages one million repetitions of one English key in each process. RSS is
peak fresh-process resident memory; binary size is the release executable.
Entries below are medians across the trials and, where available, build
repeats. The complete observed ranges are in the charts and JSONL data.

| Host | Translations | Version | First (ms) | Lookup (ns) | Runtime RSS (MB) | Binary (MB) |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| Linux | 8,000 | Upstream | 1.32 | 63.87 | 4.62 | 2.10 |
| Linux | 8,000 | PR | 1.19 | 60.32 | 3.94 | 1.51 |
| Linux | 16,000 | Upstream | 2.55 | 63.30 | 6.80 | 3.57 |
| Linux | 16,000 | PR | 2.29 | 60.57 | 5.80 | 2.46 |
| Linux | 32,000 | Upstream | 5.00 | 63.99 | 11.16 | 6.52 |

| Linux | 863,870 | PR only | 146.61 | 64.40 | 187.75 | 105.85 |
| macOS | 8,000 | Upstream | 1.54 | 47.28 | 3.72 | 1.89 |
| macOS | 8,000 | PR | 0.71 | 43.58 | 3.70 | 1.48 |

At 32k, the PR's median steady lookup was 3.4% faster on Linux and 4.2%
slower on macOS. Mac lookup trial ranges overlap. Runtime RSS at 32k was
1.84 MB lower on Linux and 0.31 MB higher on macOS. These are small,
host-specific probes of one key and one locale, not a claim that every lookup
path is regression-free. The PR executable was smaller at each completed
comparison size on both hosts.

## Method and reproduction

The hosts used Rust 1.98.1. `run_matrix.py` warms each version's dependencies,
then changes the consumer source before each timed build with one Cargo job
and incremental compilation disabled. It alternates version order at the
first three sizes and runs the candidate first at xlarge. Build time and
memory include consumer compilation and linking; they do not measure the
macro crate's own build in isolation. Runs are serialized and guarded against
process RSS, low host memory or swap, low disk space, and elapsed time. See
[`linux-metadata.json`](data/linux-metadata.json) and
[`macos-metadata.json`](data/macos-metadata.json) for exact settings.

Run locally with Python 3, Rust, Cargo, and `/usr/bin/time`:

```sh
python3 benchmarks/packed_translations/run_matrix.py \
  --main /path/to/upstream-main \
  --candidate /path/to/pr-checkout \
  --work-dir /path/to/benchmark-output \
  --warm-online
```

The script writes `metadata.json`, `results.jsonl`, and per-run logs to the
output directory. The archived JSONL and logs are in [`data`](data/).
`render_charts.py` generates the SVG and PNG charts in [`images`](images/).
